# 2단계. 화면 흐름 · 정보 구조(IA) · 기능 명세

> **한 줄 요약**: 1단계 여정에서 나온 "설계 결정"들을 **화면 몇 개에, 뭘, 어떤 순서로** 담을지 정하는 단계.
> 기준은 하나야: **내가 실제로 쓰는 도구, 결과물이 좋아야 한다.**

---

## 📚 개념 3개

| 용어 | 한마디로 | 비유 |
|---|---|---|
| **IA** (Information Architecture, 정보 구조) | 서비스에 있는 정보와 기능을 **어떤 묶음으로, 어떤 계층으로** 정리할지 | 마트 매대 배치도 |
| **화면 흐름** (Screen/User Flow) | 화면 A에서 뭘 누르면 화면 B로 가는지 | 지하철 노선도 |
| **기능 명세** (기능 정의서) | 기능 하나하나의 규칙: 언제 켜지고, 뭘 받아서, 뭘 내놓고, 실패하면 어떻게 되는지 | 레시피 |

순서는 보통 **IA → 흐름 → 명세**야. 큰 덩어리를 먼저 나누고, 그 사이 길을 잇고, 마지막에 디테일을 채워.

## 1. 첫 번째 큰 결정: 화면을 몇 개로 나눌까?

1단계 To-Be 여정은 8단계(진입 → 입력 → 직무 → 대기 → 결과 → 경고 → 복사 → 다음)였어. 그렇다고 화면도 8개를 만들어야 할까? **아니야.** 여정 단계 ≠ 화면 수야.

### 선택지 비교

| 안 | 구성 | 장점 | 단점 |
|---|---|---|---|
| A. 마법사형 | 소개 → 입력 → 직무 → 결과 (4화면) | 단계가 명확, 처음 쓰는 사람에게 친절 | 클릭 많음. 결과 보고 입력 고치려면 왔다 갔다 |
| B. 한 페이지 스크롤 | 모든 게 한 페이지에 위→아래 | 단순 | 결과가 길어지면 원문이랑 결과가 멀어져서 **대조가 어려움** |
| **C. 2화면 (입력 / 결과)** ✅ | ① 입력 화면 (경험 + 직무 한 번에) ② 결과 작업대 (원문 + 직무별 카드) | 입력은 한 번에 끝내고, 결과 화면에선 **원문과 카드가 나란히** | 처음 쓰는 사람용 소개는 짧아짐 |

### 왜 C야?
- **"내가 쓰는 도구"니까 소개 화면이 필요 없어.** 1단계에선 "처음 보는 사람이 3초 안에 이해"를 신경 썼지? 근데 매일 쓰는 도구라면 그건 첫날 한 번뿐이야. 제목 한 줄이랑 예시 버튼 하나로 충분해. → **타겟 상황이 바뀌면 설계가 바뀐다**는 걸 보여주는 좋은 예야
- 결과 화면의 핵심 동작은 **"카드 문장 ↔ 원문" 대조**야. 그러려면 둘이 한 화면에 나란히 있어야 해
- 직무 선택을 별도 화면으로 빼면 클릭만 늘어. 칩 4개는 입력 화면 아래에 둬도 충분해

## 2. IA: 정보 구조도

```
원소스
├── ① 입력 화면
│   ├── 헤더: 서비스 이름 + 한 줄 설명 ("경험 1개 → 직무별 이력서 1~2줄")
│   ├── [예시로 채워보기] 버튼
│   ├── 경험 입력
│   │   ├── 입력 방식 토글: [항목별로 쓰기] / [통째로 붙여넣기]
│   │   ├── (항목별) 활동명*, 내 역할*, 한 일*, 성과, 기간, 사용 툴, 문제 해결
│   │   ├── (통째로) 큰 텍스트 칸 1개
│   │   ├── 재료 충분도 게이지 + 안내 문구
│   │   └── 민감 정보 안내 한 줄
│   ├── 지원 직무 선택
│   │   ├── 직무 칩 4개 (각각 "이 직무가 보는 것" 한 줄)
│   │   ├── + 직접 입력
│   │   └── 직무별 채용공고(JD) 붙여넣기 (선택, 접힘)
│   ├── 세부 옵션 (접힘): 글자 수 제한
│   └── [직무별로 만들기] 버튼
│
└── ② 결과 작업대
    ├── 상단 바: [← 입력 수정] [+ 직무 추가] [새 경험]
    ├── 원문 패널 (고정)
    │   └── 사실 단위로 쪼갠 원문 (카드에서 쓰인 사실이 색으로 켜짐)
    ├── 직무별 카드 (나란히, 모바일은 탭)
    │   ├── 직무명
    │   ├── 경력 문장 (클릭하면 수정 가능) + 글자 수
    │   ├── 앞세운 사실 태그
    │   ├── 💡 왜 이렇게? (한 줄)
    │   ├── 검사 결과: ✓ 원문과 일치 / ⚠️ 경고 N개 (펼치면 상세)
    │   └── [복사] [이 직무만 다시]
    └── 차이가 작을 때 안내 배너 ("재료를 더 넣으면 직무별 차이가 커져요")
```

💡 **기획자 팁**: IA를 짤 때 **"이게 없으면 사용자가 일을 못 끝내나?"**를 계속 물어봐. 못 끝내면 바로 보이는 곳에, 있으면 좋은 정도면 접어두는 거야. 위에서 `(선택, 접힘)`이 붙은 게 그렇게 분류된 것들이야.

## 3. 화면 흐름

```
                ┌────────────────────────────┐
  처음 열기 ───▶│        ① 입력 화면          │◀──── 저장된 입력 있으면 자동 복구
                │  경험 입력 + 직무 선택       │
                └──────────┬─────────────────┘
                           │ [직무별로 만들기]
                           │ (필수 3칸 + 직무 2개 이상일 때만 켜짐)
                           ▼
                ┌────────────────────────────┐
                │   생성 중 (같은 화면 위 오버레이) │
                │ 역량 파악 → 사실 선택 → 문장 → 대조 │
                └──────┬───────────┬─────────┘
                  성공 │           │ 실패
                       ▼           ▼
   ┌──────────────────────┐   입력 화면 그대로 + 에러 메시지 + [다시 시도]
   │    ② 결과 작업대       │
   │                      │── [← 입력 수정] ──▶ ① (입력값 유지, 결과는 보관)
   │ 카드 문장 수정 → 즉시 재검사 │── [+ 직무 추가] ──▶ 칩 선택 팝업 → 새 카드만 생성
   │ [이 직무만 다시] → 그 카드만 재생성 │── [새 경험] ──▶ 확인창 → ① (빈 상태)
   │ [복사] → "복사함" 표시   │
   └──────────────────────┘
```

### 흐름에서 정한 규칙
1. **입력은 절대 안 날아간다**: 실패해도, 뒤로 가도, 새로고침해도 유지돼 (브라우저 임시 저장)
2. **재생성은 카드 단위**: 마케팅 카드가 마음에 안 든다고 다른 카드까지 다시 만들지 않아. 마음에 드는 걸 지키는 게 중요해
3. **되돌릴 수 없는 동작만 확인창**: `새 경험`(결과 사라짐)만 물어보고, 나머지는 바로 실행

## 4. 기능 명세

우선순위는 **MoSCoW**로 표시했어:
**M**ust(없으면 서비스가 안 됨) / **S**hould(있어야 쓸 만함) / **C**ould(여유 있으면) / **W**on't(이번엔 안 함)

### ① 입력 화면

| ID | 기능 | 규칙 | 우선 |
|---|---|---|---|
| IN-1 | 항목별 입력 | 필수: 활동명, 내 역할, 한 일. 선택: 성과, 기간, 사용 툴, 문제 해결. 칸마다 예시 placeholder | M |
| IN-2 | 통째로 붙여넣기 | 큰 칸 1개. 이 모드에선 "한 일" 칸에 내용이 있으면 필수 조건 충족으로 봄 | S |
| IN-3 | 재료 충분도 | 입력에서 **사실 개수**(줄바꿈·쉼표·마침표 기준)와 **숫자 유무**를 세서 3단계로 표시. 부족: "사실 2개뿐이라 직무별로 비슷하게 나올 수 있어요" / 보통 / 충분 | S |
| IN-4 | 직무 선택 | 칩 4개 다중 선택 + 직접 입력(최대 1개 추가). **2개 이상**일 때 생성 버튼 켜짐. 최대 4개 | M |
| IN-5 | 직무 설명 | 칩마다 "이 직무가 보는 것" 한 줄 (아래 직무 사전 참고) | S |
| IN-6 | JD 붙여넣기 | 선택한 직무마다 접힌 칸. 있으면 AI가 JD 키워드를 우선 반영 | C |
| IN-7 | 글자 수 제한 | 기본 80자 안팎. 숫자를 넣으면 그 안으로 | S |
| IN-8 | 예시로 채우기 | 기획서 3장 공모전 예시로 전체를 채움 | S |
| IN-9 | 임시 저장 | 입력할 때마다 브라우저에 저장, 다시 열면 복구 | M |

### ② 생성 (AI + 코드)

| ID | 기능 | 규칙 | 우선 |
|---|---|---|---|
| GEN-1 | 동시 생성 | 선택한 직무 전부를 **한 번의 AI 호출**로 생성 (직무끼리 서로 다르게 쓰도록 AI가 한꺼번에 보고 판단하게) | M |
| GEN-2 | 단계 로딩 | 4단계 문구를 순서대로 보여줌 | S |
| GEN-3 | 실패 처리 | AI 응답이 형식에 안 맞으면 자동으로 1회 재요청 → 그래도 실패하면 에러 + [다시 시도] | M |
| GEN-4 | 카드 단위 재생성 | 그 직무만 다시. 이때 **다른 카드의 문장을 AI에게 같이 보내서** "이것들과 다르게" 쓰게 함 | S |
| GEN-5 | 직무 추가 | 결과 화면에서 직무를 추가하면 그 직무만 새로 생성 (GEN-4와 같은 방식) | S |

### ③ 결과 작업대

| ID | 기능 | 규칙 | 우선 |
|---|---|---|---|
| OUT-1 | 직무별 카드 | 데스크톱: 나란히(2~4열). 모바일: 탭 | M |
| OUT-2 | 재구성 이유 | 카드마다 한 줄. "이 직무는 ○○를 보기 때문에 △△를 앞에 뒀어요" 형식 | M |
| OUT-3 | 앞세운 사실 태그 | 문장에 쓰인 사실을 짧은 태그로 (최대 3개) | S |
| OUT-4 | 근거 하이라이트 | 카드에 마우스를 올리거나 탭하면 → 원문 패널에서 그 카드가 쓴 사실들이 색으로 켜짐. 문장 속 구절에 올리면 그 구절의 근거 사실만 진하게 | M |
| OUT-5 | 규칙 검사 | 아래 "검사 규칙" 참고. **AI가 아니라 코드가 함** | M |
| OUT-6 | 문장 직접 수정 | 문장 클릭 → 편집. 입력할 때마다 글자 수, 검사 결과 갱신 | M |
| OUT-7 | 복사 | 클릭 → 클립보드 → "복사했어요" + 카드에 `✓ 복사함 23:14` | M |
| OUT-8 | 차이 경고 배너 | 카드끼리 문장이 너무 비슷하면(코드로 유사도 계산) 배너 표시 | C |
| OUT-9 | 글자 수 표시 | `76자 / 80자`. 넘으면 빨간색 | M |
| — | 경험 보관함, 버전 기록, 계정, PDF 내보내기 | 기획서 MVP 범위 밖 | W |

## 5. 핵심 설계: 근거 하이라이트를 어떻게 구현할까?

여기가 이 서비스에서 기술적으로 제일 까다로운 부분이라 따로 정리했어. **MVP 제작 담당이면 팀에 꼭 설명할 수 있어야 하는 부분**이야.

### 문제
"이 문장의 이 구절이 원문 어디서 왔는지"를 어떻게 알아내지?

### 방법: "사실 번호표" 방식
1. **AI가 원문을 사실 단위로 쪼개고 번호를 붙여.** 이때 규칙: 원문 표현을 **그대로 인용**해야 해 (요약 금지)
   - F1 "5인 팀 구성" / F2 "SNS 콘텐츠 20건 기획·제작" / F3 "팔로워 참여율 15% 증가" …
2. **AI가 직무별 문장을 쓸 때, 구절마다 어느 사실에서 왔는지 번호를 달아.**
   - 마케팅: [`SNS 콘텐츠 20건 기획·제작으로` ← F2] [`팔로워 참여율 15% 향상` ← F3]
3. **코드가 확인해**: F1, F2… 인용문이 원문에 진짜 있는지 (없으면 그 사실은 "출처 불명" 처리)
4. 화면에서는 번호로 원문과 카드를 이어서 색칠해

### AI가 돌려줄 데이터 모양 (예시)
```json
{
  "facts": [
    { "id": "F2", "quote": "SNS 콘텐츠 20건 기획·제작" },
    { "id": "F3", "quote": "팔로워 참여율 15% 증가" }
  ],
  "results": [
    {
      "job": "마케팅",
      "segments": [
        { "text": "SNS 콘텐츠 20건 기획·제작으로 ", "facts": ["F2"] },
        { "text": "팔로워 참여율 15% 향상", "facts": ["F3"] }
      ],
      "reason": "마케팅은 콘텐츠 실행력과 대상자 반응을 보기 때문에 콘텐츠 건수와 참여율을 앞에 뒀어요",
      "tags": ["콘텐츠 20건", "참여율 15%"]
    }
  ]
}
```

💡 **기획자 팁**: AI 서비스를 기획할 땐 **"AI한테 뭘 받아야 화면을 그릴 수 있지?"**를 꼭 정해야 해. 화면에 "근거 하이라이트"를 그리려면 AI가 근거 번호를 줘야 하잖아. 이걸 안 정하고 "AI가 알아서 해주겠지" 하면 제작 단계에서 막혀. **화면 설계와 AI 출력 설계는 한 몸**이야.

## 6. 검사 규칙 (코드가 하는 일)

AI가 스스로 "원문에 없는 내용 없음"이라고 판정하면 못 믿어 (기획서 7장, AI 자기검증의 한계). 그래서 **코드가 기계적으로** 대조해.

| 규칙 | 검사 방법 | 예시 | 표시 |
|---|---|---|---|
| R1. 숫자 | 문장 속 숫자(+단위)가 원문에 있는지. 표기 차이는 같은 걸로 봄: `10곳 = 열 곳`, `15% = 15 %`, `3주 = 삼 주` | "매출 30% 증가" → 원문에 30 없음 | ⚠️ 원문에 없는 숫자 '30%' |
| R2. 역할 부풀리기 | 문장에 "주도·총괄·리드·책임·기획" 같은 역할 동사가 있는데 원문엔 없을 때 | 원문 "참여" → 문장 "주도" | ⚠️ 원문보다 강한 역할 표현 '주도' |
| R3. 출처 불명 사실 | AI가 준 사실 인용문이 원문에서 안 찾아질 때 (띄어쓰기 무시하고 비교) | AI가 "협찬 매출 증가"를 사실로 만들어냄 | ⚠️ 원문에서 못 찾은 내용 |
| R4. 글자 수 | 제한 초과 | 92자 / 80자 | 빨간 글자 수 |

경고가 하나도 없으면 `✓ 숫자·역할 표현이 원문과 일치해요`를 보여줘. **검사했다는 사실 자체가 안심 장치**야.

## 7. 직무 사전 (칩 설명 + AI 지시에 같이 씀)

기획서 7장 "직무 역량 분석" 예시를 바탕으로 정리했어.

| 직무 | 칩 설명 (화면) | 앞세울 사실 (AI 지시) | 자주 쓰는 용어 |
|---|---|---|---|
| 마케팅 | 대상자 반응과 콘텐츠 성과를 봐요 | 콘텐츠 기획·제작 건수, 반응·참여·도달 수치, 타깃 설정 | 참여율, 도달, 타깃, 콘텐츠, 캠페인 |
| 서비스기획·PM | 문제 정의, 일정, 협업 조율을 봐요 | 문제 발견→해결 과정, 일정 준수, 이해관계자 조율, 개선 결과 | 일정 관리, 이해관계자, 요구사항, 개선 |
| 영업관리 | 관계 구축과 숫자로 된 성과를 봐요 | 섭외·협상 건수, 예산·매출·계약 성과, 외부 관계자 관리 | 섭외, 협상, 거래처, 예산 확보, 목표 달성 |
| 인사 | 사람 사이 조율과 구성원 이해를 봐요 | 팀 구성·역할 분배, 갈등 조율, 구성원 의견 수렴, 운영 | 조율, 소통, 구성원, 운영, 온보딩 |
| 직접 입력 | (사용자가 쓴 직무명) | AI가 그 직무에서 보는 역량을 스스로 판단 | — |

## 8. 2단계 정리: 이번에 배운 것

1. **여정 단계 수 ≠ 화면 수**: 8단계 여정을 화면 2개에 담았어
2. **타겟 상황이 설계를 바꾼다**: "내가 매일 쓰는 도구"가 되니까 소개 화면이 거의 사라졌어
3. **IA는 "없으면 일을 못 끝내나?"로 위계를 정한다**
4. **흐름엔 실패 경로와 되돌아가기를 꼭 넣는다**
5. **AI 서비스는 "AI에게 받을 데이터 모양"까지 기획한다**
6. **검사는 AI 말고 코드로**: 믿을 수 있는 건 기계적 대조야
