## 0단계에서 확정한 것

| 질문 | 결정 | 이유 |
|---|---|---|
| AI를 진짜로 돌릴까? | 진짜 Claude 연결 (claude.ai 아티팩트) | 아무 경험이나 넣어도 진짜 결과가 나와야 실제로 쓸 수 있음. API 키 없이 claude.ai 안에서 돌아감 |
| 입력 방식 | 항목형 + 줄글 붙여넣기 보조 | 기획서 7장(항목형)과 8장(줄글)이 충돌. 7장의 "짧은 입력 → 직무별 문장 똑같아짐" 위험을 막으려면 재료를 칸으로 받아야 함 |
| 진행 방식 | 단계마다 멈추고 리뷰 | 학습 목적 |

## 1단계 리뷰에서 확정한 것

| 질문 | 결정 | 이유 |
|---|---|---|
| 결과 문장을 화면에서 직접 고칠 수 있게? | 고칠 수 있게 + 고치면 바로 다시 검사 | 기획서 8장 Action "경고 구간 수정". 고친 문장도 검사를 통과해야 안심하고 복사 가능 |
| 직무 목록 | 마케팅 / 서비스기획·PM / 영업관리 / 인사 + 직접 입력 | 기획서에 나온 직무 전부 + 확장 여지 |
| 테스트 관련 장치 (측정 로그, 테스터 안내 등) | **전부 뺌** | 테스트는 과제 제출용. 프로토타입은 "내가 실제로 쓰는 도구"로서 결과물 품질에 집중 |

## 2단계 리뷰에서 확정한 것

| 질문 | 결정 | 이유 |
|---|---|---|
| 화면 구성 | 2화면 (입력 / 결과 작업대) | 내가 쓰는 도구라 소개 화면 불필요. 원문과 카드를 나란히 놓고 대조해야 함 |
| 직무당 문장 수 | 1개 + [이 직무만 다시] | 카드가 깔끔하고 비교가 쉬움 |
| 경험 보관함 | **넣음** (브라우저 저장, 목록·불러오기·삭제) | 기획서 MVP에선 제외였지만 실제로 쓰려면 필요. 서버 저장은 여전히 없음 |
| 근거 하이라이트 구현 | AI가 원문을 "사실 번호표"로 쪼개고, 문장 구절마다 번호를 붙임 → 코드가 원문과 대조 | 화면에 근거를 그리려면 AI 출력에 근거 번호가 있어야 함 |
| 검사 주체 | AI가 아니라 코드 (숫자, 역할 동사, 출처 불명, 글자 수) | AI 자기검증은 못 믿음 (기획서 7장) |

## 3단계 리뷰에서 확정한 것

| 질문 | 결정 | 이유 |
|---|---|---|
| 결과 화면 레이아웃 | 원문 왼쪽 고정 + 카드 2열 | 원문을 항상 보면서 대조. 직무가 4개면 2×2 |

## 4단계 리뷰에서 추가한 것

| 요청 | 결정 | 이유 |
|---|---|---|
| JD에 맞춰줬으면 | 채용공고를 **지원 대상**으로 추가 (직무 칩과 섞어서 최대 4개, 결과 화면에서도 추가 가능) | 실제 지원은 공고 단위. 같은 직무 공고 2개도 동시에 비교 가능 |

## 외부 공유 방법

| 누가 | 링크 | AI 동작 | 비고 |
|---|---|---|---|
| 직접 써볼 사람 (팀원·교수님) | [claude.ai 아티팩트](https://claude.ai/artifact/JKUtkZGoabDuFt1qcLYJHW) | ⭕ (claude.ai 로그인 필요, 그 사람 계정 사용량 사용) | 아티팩트 페이지의 **공유(Share) 메뉴**에서 공유 범위를 열어야 다른 사람이 열 수 있음 |
| 구경만 할 사람 (발표·제출·포트폴리오) | https://chaesilver47-cell.github.io/1/ | ❌ 예시 결과만 | GitHub Pages. 저장소 Settings → Pages에서 켜야 함 (아래) |

**GitHub Pages 켜는 법**: 저장소 Settings → Pages → Build and deployment → Source: *Deploy from a branch* → Branch: `docs/`가 들어 있는 브랜치 선택, 폴더 `/docs` → Save. 1~2분 뒤 위 주소로 열림.
와이어프레임은 `/1/wireframe/`에 같이 올라가.

**프로토타입을 고친 뒤에는** `./onesource/build-pages.sh`를 한 번 돌려야 `docs/`(공개 주소용 사본)도 갱신돼.

## 다른 사람이 "자기 계정으로" 쓰게 하기 (API 키 없이)

Claude Code에서 올린 아티팩트는 **다른 계정이 열면 Claude 연결을 받지 못한다**. 그래서 다른 사람에게 쓰게 할 때는 **claude.ai 채팅 아티팩트(AI 앱)**로 공개한다.
쓰는 사람은 자기 Claude 계정으로 로그인하고, 사용량도 그 사람 구독에서 나간다 (공식 안내: claude.com/blog/claude-powered-artifacts).

1. claude.ai에서 새 채팅 → `docs/index.html` 첨부
2. "첨부한 index.html을 한 글자도 바꾸지 말고 그대로 HTML 아티팩트로 만들어줘" 라고 보내기
3. 만들어진 아티팩트에서 공개(Publish) → 링크 공유

페이지는 `window.claude.complete`(채팅 아티팩트)와 `claude.use("sample")`(Claude Code 아티팩트)를 둘 다 지원한다.

## 다른 사람에게 쓰게 하기: "복제" 방식 (확정)

- Claude Code에서 올린 아티팩트는 **주인이 아닌 계정이 열면 AI 연결을 받지 못한다** (개인 계정으로도 확인: `Claude: 없음 · 권한: 확인 불가 · 377ms`).
- 대신 **복제**하면 복제한 사람이 주인이 되어 자기 Claude로 쓸 수 있다.
- 원본 링크를 남이 열면 맨 위에 "복제해서 내 계정으로 가져가면 바로 쓸 수 있어요" 안내가 뜬다.
- 복제본 주인이 열면 "내 사본에 이름 붙이기 · OneSource ( 이름 )" 버튼이 뜬다. 누르면 페이지가 제목을 바꿔 스스로 다시 저장한다 (`artifact` + `user` 기능).
- 이를 위해 빌드 때 페이지 소스 전체를 `SELF_T`에 넣는다: `prototype/index.html`(소스) → `./onesource/build-pages.sh` → `prototype/publish.html`(올리는 파일), `docs/index.html`(Pages).

## 5단계 전 추가 기능 (사용 피드백 반영)

| 요청 | 결정 | 이유 |
|---|---|---|
| 팝업에 로그인 필요 안내 | "claude.ai 로그인이 필요해요. 쓰는 만큼 내 계정 사용량에서 나가요" | 복제해도 로그인 안 하면 못 씀 |
| 직무 1개만 골라도 | 지원 대상 1~4개 | 공고 하나에만 맞추고 싶은 경우가 대부분 |
| 채용공고 붙여넣기가 기본 | 2번 섹션 맨 위에 공고 칸이 펼쳐져 있고, 직무 칩은 "공고가 없으면" 아래로. 공고를 써두고 [공고 추가]를 안 눌러도 지원 대상에 포함 | 실제 지원은 공고 단위 |
| 보관함 → **내 창고** | 문장 창고(☆ 넣기, 복사하면 자동 저장 + "어디에 냈어요?" 기록), 대상별 필터·검색, 여러 개 골라 **한꺼번에 복사**(경력란 한 벌), 경험 탭, 제출 기록 탭 | 지원할 때는 경험 여러 개의 문장이 한 번에 필요하고, 어디에 냈는지 기억해야 함 (인터뷰이 C) |
| 다시 만들면 예전 문장이 사라짐 | 카드마다 "이전 버전" 최대 5개 + 되돌리기 | 마음에 들던 문장을 잃지 않게 |
| 글자 수만 바꾸기 | 카드마다 글자 수 입력 → [이 길이로]: 강조점·순서는 유지하고 길이만 다시 씀 | 지원서마다 글자 제한이 다름 |
| 개요식 변환 | 카드마다 [줄글 \| 개요식] 전환. 개요식은 "- " 불릿 2~4줄. 복사·창고 저장은 보이는 형식 그대로 | 줄바꿈 되는 칸에는 개요식이 읽기 좋음 |
