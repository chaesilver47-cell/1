# 원소스(OneSource) 프로토타입 제작 노트

> 기획서(Team13 제안서)를 받아서 → 사용자 여정 분석 → 화면 설계 → 프로토타입까지 직접 가보는 기록.
> 각 단계마다 "기획자는 여기서 뭘 하고, 왜 하는지"를 같이 적어둠.

## 전체 로드맵

| 단계 | 하는 일 | 산출물 | 상태 |
|---|---|---|---|
| 0 | 기획서 읽고 정해진 것 / 안 정해진 것 구분 | 질문 목록 → 팀 결정 | ✅ |
| 1 | **사용자 여정 분석** (지금 vs 원소스 쓸 때, 클릭 단위로) | [01_user_journey.md](./01_user_journey.md) | ✅ |
| 2 | 기능 명세 + 정보 구조(IA) + 화면 흐름 | [02_screen_flow.md](./02_screen_flow.md) | ✅ |
| 3 | 와이어프레임 (화면별 뼈대) | 03_wireframe.md | ⏳ |
| 4 | 프로토타입 제작 (진짜 Claude 연결) | prototype/index.html + 아티팩트 링크 | ⏳ |
| 5 | 직접 써보고 결과물 품질 다듬기 (프롬프트·검사 규칙 개선) | 05_tuning.md | ⏳ |

## 0단계에서 확정한 것

| 질문 | 결정 | 이유 |
|---|---|---|
| AI를 진짜로 돌릴까? | 진짜 Claude 연결 (claude.ai 아티팩트) | 아무 경험이나 넣어도 진짜 결과가 나와야 실제로 쓸 수 있음. API 키 없이 claude.ai 안에서 돌아감 |
| 입력 방식 | 항목형 + 줄글 붙여넣기 보조 | 기획서 7장(항목형)과 8장(줄글)이 충돌. 7장의 "짧은 입력 → 직무별 문장 똑같아짐" 위험을 막으려면 재료를 칸으로 받아야 함 |
| 진행 방식 | 단계마다 멈추고 리뷰 | 학습 목적 |

## 1단계 리뷰에서 확정한 것

| 질문 | 결정 | 이유 |
|---|---|---|
| 결과 문장을 화면에서 직접 고칠 수 있게? | 고칠 수 있게 + 고치면 바로 다시 검사 | 기획서 8장 Action "경고 구간 수정". 고친 문장도 검사를 통과해야 안심하고 복사 가능 |
| 직무 목록 | 마케팅 / 서비스기획·PM / 영업관리 / 인사 + 직접 입력 | 기획서에 나온 직무 전부 + 확장 여지 |
| 테스트 관련 장치 (측정 로그, 테스터 안내 등) | **전부 뺌** | 테스트는 과제 제출용. 프로토타입은 "내가 실제로 쓰는 도구"로서 결과물 품질에 집중 |

## 2단계 리뷰에서 확정한 것

| 질문 | 결정 | 이유 |
|---|---|---|
| 화면 구성 | 2화면 (입력 / 결과 작업대) | 내가 쓰는 도구라 소개 화면 불필요. 원문과 카드를 나란히 놓고 대조해야 함 |
| 직무당 문장 수 | 1개 + [이 직무만 다시] | 카드가 깔끔하고 비교가 쉬움 |
| 경험 보관함 | **넣음** (브라우저 저장, 목록·불러오기·삭제) | 기획서 MVP에선 제외였지만 실제로 쓰려면 필요. 서버 저장은 여전히 없음 |
| 근거 하이라이트 구현 | AI가 원문을 "사실 번호표"로 쪼개고, 문장 구절마다 번호를 붙임 → 코드가 원문과 대조 | 화면에 근거를 그리려면 AI 출력에 근거 번호가 있어야 함 |
| 검사 주체 | AI가 아니라 코드 (숫자, 역할 동사, 출처 불명, 글자 수) | AI 자기검증은 못 믿음 (기획서 7장) |
