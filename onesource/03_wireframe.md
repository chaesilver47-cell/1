## 📚 와이어프레임이 뭐야?

집 짓기로 비유하면:

| 단계 | 집 | 서비스 |
|---|---|---|
| IA | 방이 몇 개고 뭐가 어디 있는지 | 화면 구성, 정보 묶음 |
| **와이어프레임** | **평면도**: 벽, 문, 가구 자리 | **화면 뼈대**: 영역, 버튼, 글 위치 |
| 디자인 시안 | 인테리어: 벽지, 조명 | 색, 폰트, 아이콘 |
| 프로토타입 | 모델하우스 | 진짜로 눌러지고 돌아가는 화면 |

와이어프레임에서 **일부러 회색으로만 그리는 이유**: 색이 들어가면 "이 파란색 별론데?" 같은 얘기로 빠져. 지금은 **"이 정보가 여기 있는 게 맞나?"**만 보려는 거야.

> 💡 이번 와이어프레임은 버튼 몇 개가 실제로 눌러져. 이런 걸 **클릭 가능한 와이어프레임**(lo-fi 프로토타입)이라고 해. 가만히 있는 그림으로는 "결과 카드에 마우스를 올리면 원문이 켜진다" 같은 **동작**을 확인하기 어렵거든.

## 화면별 핵심 (자세한 설명은 와이어프레임 오른쪽 패널에 있어)

| 화면 | 이 화면의 목표 | 제일 중요한 설계 |
|---|---|---|
| ① 입력 | 노션 원문을 2~3분 안에 옮기고 재료 확보 | 필수 3칸만 보이게, 재료 충분도 게이지, 버튼이 왜 꺼졌는지 알려줌 |
| ② 생성 중·에러 | 기다리는 동안 불안하지 않게 | 4단계 로딩, 에러 나도 입력 유지 |
| ③ 결과 작업대 | 직무별 차이가 한눈에 보이게 | 원문 패널 고정 + 마우스를 올리면 근거가 켜짐 |
| ④ 경고·수정 | 경고 뜬 곳만 보고 고치기 | 경고 = 무엇이 + 왜 + 행동 버튼 3개, 직접 고쳐도 다시 검사 |
| ⑤ 보관함 | 지난 경험 다시 꺼내기 | 옆에서 열리는 패널, ✓ = 복사한 직무 |
| ⑥ 모바일 | 폰에서도 쓸 수는 있게 | 원문은 접어서 위로, 카드는 탭으로 |

## 그리면서 새로 정한 것들

와이어프레임을 실제로 그려보면 문서로는 안 보이던 게 보여. 이번에 나온 것들:

1. **버튼이 꺼져 있을 때 이유를 옆에 써준다**: 회색 버튼만 있으면 "왜 안 눌리지?" 하고 답답해
2. **경고에는 꼭 행동 버튼을 붙인다**: 경고만 띄우면 사용자가 다음에 뭘 해야 할지 몰라. `지우기` / `직접 고치기` / `이 직무만 다시`
3. **내가 직접 고친 문장도 검사한다**: 내가 "주도적으로"를 넣으면 나한테도 경고가 떠
4. **원래대로 버튼**: 고치다 망치면 AI가 처음 쓴 문장으로 돌아가
5. **보관함 항목의 ✓ 표시**: 어느 직무 버전을 복사했는지 남겨둬 (인터뷰이 C의 "어디에 뭘 냈는지 헷갈림")

💡 **기획자 팁**: 와이어프레임을 그리면서 **"이 버튼 누르면 그다음엔?"**을 계속 물어봐. 답이 없는 버튼이 있으면 아직 기획이 덜 된 거야.

## 3단계 정리: 이번에 배운 것

1. 와이어프레임은 **평면도**다. 색은 빼고 위치와 위계만 본다
2. **동작이 중요한 화면은 클릭 가능하게** 만들어 본다
3. 화면마다 **목표를 한 문장으로** 적어두면 뭘 넣고 뺄지 판단이 쉬워진다
4. 그려보면 문서에서 안 보이던 **빈칸**이 나온다 (꺼진 버튼, 경고 다음 행동)
