## 1. 전체 구조: 버튼 하나 누르면 무슨 일이 일어나?

```
[직무별로 만들기] 클릭
   │
   ├─① 입력값 + 직무 사전 + 문장 규칙 → 지시문(프롬프트) 1개로 조립
   │
   ├─② Claude 호출 (1번)  ──▶  JSON으로 답이 옴
   │      facts:   원문을 사실 단위로 쪼갠 것 (F1, F2 …, 원문 그대로 인용)
   │      results: 직무별 문장 조각(segments) + 근거 번호 + 이유 + 태그
   │
   ├─③ 코드 검사 (AI 아님)
   │      - F1, F2 … 인용이 원문에 진짜 있나?    → 없으면 "원문에서 못 찾은 내용"
   │      - 문장 속 숫자가 원문에 있나?            → 없으면 "원문에 없는 숫자"
   │      - 주도·총괄·리드 같은 역할 표현이 원문보다 센가? → "원문보다 강한 역할 표현"
   │      - 글자 수 제한 넘었나?
   │      - 직무별 문장끼리 너무 비슷한가?         → "재료를 더 넣어보세요" 안내
   │
   ├─④ 보관함에 자동 저장
   │
   └─⑤ 결과 작업대 표시
```

💡 **기획자 팁**: 이 그림을 팀에 설명할 수 있으면 "AI가 알아서 해줘요"가 아니라 **"AI는 ②만 하고, 믿을 수 있는지는 ③에서 코드가 확인해요"**라고 말할 수 있어. 기획서 7장 원칙("AI는 초안, 사람은 판단")을 구조로 보여주는 거야.

## 2. 프롬프트 설계: 기획 문서가 그대로 AI 지시문이 됐어

앞 단계에서 만든 문서들이 이렇게 들어갔어:

| 프롬프트 부분 | 어디서 왔어? |
|---|---|
| "너는 이력서 경력·대내외활동 칸을 직무별로 다시 쓰는 편집자야" | 기획서 1장 (자소서가 아님!) |
| `[원문]` 항목별 입력 | 2단계 IA 입력 칸 |
| `[지원 직무]` 이 직무가 보는 것 / 앞세울 사실 / 용어 | 2단계 직무 사전 |
| `[할 일]` 사실 쪼개기 → 사실 고르기 → 문장 쓰기 | 기획서 8장 AI 흐름 |
| `[문장 규칙]` 짧게, 이력서 문체, 숫자 지어내기 금지, 역할 부풀리기 금지, 직무마다 다르게 | 1단계 "좋은 1~2줄" 기준표 |
| `[출력]` facts / segments / reason / tags 모양 | 2단계 "AI가 돌려줄 데이터 모양" |

**→ 기획 문서를 꼼꼼히 쓸수록 프롬프트가 좋아져.** AI 서비스에서 기획자의 글쓰기가 곧 제품 품질이 되는 이유야.

### 다시 만들기(카드 하나만)는 프롬프트가 달라
- 이미 뽑아둔 사실 번호(F1…)를 **고정해서** 줘. 그래야 원문 하이라이트가 안 꼬여
- **다른 직무 카드의 문장을 같이 줘서** "이것들과 겹치지 않게" 써달라고 해
- `문제 빼고 다시 만들기`를 누르면 **걸렸던 경고 내용도 같이 줘서** 같은 실수를 반복하지 않게 해

## 3. 만들면서 와이어프레임과 달라진 것 (그리고 이유)

프로토타입을 만들다 보면 와이어프레임에서 괜찮아 보였던 게 실제로는 안 되는 경우가 생겨. 이것도 중요한 배움이야.

| 와이어프레임 | 프로토타입 | 왜 바꿨어? |
|---|---|---|
| 경고에 `이 부분 지우기` 버튼 | `문제 빼고 다시 만들기`로 교체 | "협찬처 10곳을 섭외해 **협찬 매출 30% 증가**"에서 문제 부분만 지우면 "섭외해"로 끝나서 문장이 깨져. 지우기보다 **문제를 알려주고 다시 쓰게** 하는 게 결과물이 좋아 |
| 로딩: 역량 파악 → 사실 선택 → 문장 → 대조 | 생각 중 → **사실 나누는 중** → 문장 쓰는 중 **(2/3)** → 대조 중 | AI 답이 실시간으로 들어오는 걸 보고 **실제 진행 상황**에 맞춰 단계를 넘겨. 시간 맞춰 가짜로 넘기는 것보다 정직해 |
| 처음 열면 빈 입력 화면 | 처음 한 번은 **예시 경험이 채워진 채로** 시작 | 빈 화면은 이 도구가 뭘 하는지 안 보여줘. 버튼 한 번에 결과를 볼 수 있게 했어 |
| — | **예시 결과 보기** (AI 연결이 안 될 때) | claude.ai 밖에서 열거나 AI 연결이 막히면, 미리 만들어둔 결과로라도 화면을 볼 수 있게 했어 |
| — | 수정 중엔 `원래대로` 버튼이 항상 보임 | 고치다 망쳐도 바로 되돌릴 수 있게 |
| 결과 숫자 표기 차이 | "10곳" = "열 곳" 같은 걸로 봐 | 오탐(괜히 경고 뜨는 것)이 쌓이면 경고를 무시하게 돼 |

## 4. 검사 규칙: 실제로 어떻게 판단해?

| 규칙 | 경고 뜨는 예 | 경고 안 뜨는 예 |
|---|---|---|
| 숫자 | 원문엔 15%인데 문장엔 "30%" | "10곳" ↔ 원문 "열 곳" (같은 숫자로 봄) |
| 역할 | 원문에 없는 "총괄", "전담", "단독" | 역할이 "팀장"이면 "이끌며", "주도" 정도는 허용 |
| 출처 | AI가 근거로 댄 "협찬 매출 크게 증가"가 원문에 없음 | 띄어쓰기·가운뎃점 차이는 무시하고 비교 |
| 글자 수 | 92자 / 80자 → 빨간색 | — |
| 비슷함 | 직무별 문장의 글자 조각이 절반 넘게 겹침 → 안내 배너 | — |

⚠️ **한계도 알고 있어야 해**: 이 규칙은 숫자랑 정해둔 역할 단어만 잡아. "좋은 반응을 얻음"처럼 **숫자 없는 과장**은 못 잡아. 그래서 근거 하이라이트(원문 대조)가 같이 있는 거야. 규칙 검사와 사람 확인으로 두 번 점검하는 거지(기획서 7장).

## 5. 직접 써볼 때 이렇게 해봐

1. 링크 열기 → 예시가 채워져 있으면 그대로 `직무별로 만들기`
2. 처음 한 번 뜨는 "Claude 사용 허용" 창에서 허용
3. 결과에서 **카드에 마우스 올리기** → 원문이 형광펜으로 켜지는지
4. 문장을 눌러서 일부러 "주도적으로"나 "50%"를 넣어보기 → 경고가 바로 뜨는지
5. `새 경험` → 내 진짜 경험 하나 넣어보기
6. 결과물을 1단계 "좋은 1~2줄" 기준표로 채점해보기 → 이게 5단계(품질 다듬기)의 재료야

## 4단계 정리: 이번에 배운 것

1. **기획 문서 = AI 지시문**: 기준표, 직무 사전, 데이터 모양이 그대로 프롬프트가 됐어
2. **AI와 코드의 역할을 나눈다**: AI는 쓰고, 코드는 의심한다
3. **만들다 보면 와이어프레임이 틀린 곳이 보인다**: "지우기" 버튼처럼. 바꾼 이유를 기록해두면 팀에 설명하기 쉬워
4. **빈 화면 말고 일하는 화면으로 시작한다**
5. **한계를 문서에 적는다**: 못 잡는 게 뭔지 알아야 다음에 뭘 고칠지 정할 수 있어
